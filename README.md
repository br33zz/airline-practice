# Система управления авиакомпанией

Flutter Web-приложение для управления рейсами, самолётами, пилотами, услугами и пассажирами. В ПР6 интерфейс адаптирован для ширины от 360 до 1920 пикселей, добавлены виджет-тесты, оптимизирована первая загрузка и настроена публикация.

Опубликованный клиент: <https://br33zz.github.io/airline-practice/>.

GitHub Pages размещает только статический клиент. Для операций с данными используется локальный mock API по инструкции ниже. Адрес другого HTTPS API можно передать через переменную репозитория `API_BASE_URL`.

## Запуск

В первом терминале:

```powershell
node api/mock-server.js --port 8080 --origin http://localhost:5555
```

Во втором терминале:

```powershell
flutter pub get
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://localhost:8080/api
```

Проверка сервера: <http://localhost:8080/api/__health>.

Учётные записи:

- `reader / reader123!` — пассажир;
- `operator / operator123!` — диспетчер;
- `admin / admin123!` — администратор.

Для проверки автоматического обновления токена сервер запускается с коротким TTL:

```powershell
node api/mock-server.js --ttl 60 --port 8080 --origin http://localhost:5555
```

## Реализовано

- регистрация, вход, выход и восстановление сессии из `localStorage`;
- автоматическая подстановка `Authorization`, обновление access-токена при 401 и однократный повтор запроса;
- защита маршрутов и возврат на исходный адрес после входа;
- роли пассажира, диспетчера и администратора с разными разделами и операциями;
- обработка серверного 403 и скрытие недоступных элементов интерфейса;
- выход после 3 минут бездействия с предупреждением за 30 секунд;
- ограничение общей длительности сессии 30 минут;
- полный CRUD через API для пяти сущностей;
- логическое и физическое удаление, восстановление и множественное удаление;
- собственные исключения сетевого слоя без упоминаний Dio в виджетах;
- обработка 401, 403, 404, 409, 422 и 5xx;
- вывод ошибок 422 возле полей номера рейса и почты пассажира;
- серверные поиск, фильтрация, сортировка и пагинация;
- отмена устаревшего поискового запроса через `CancelToken`;
- до трёх попыток чтения при сетевом сбое с растущей паузой;
- однократное кэширование справочников самолётов, пилотов и услуг;
- блокировка кнопки формы во время сохранения;
- журналирование метода, адреса и кода ответа в режиме отладки;
- состояния загрузки, данных, пустого результата и ошибки с кнопкой повтора.

## Демонстрационные режимы

Задержка запросов для проверки индикатора загрузки:

```powershell
flutter run -d chrome --web-port=5555 --dart-define=API_DEMO_DELAY=1500
```

Принудительная ошибка 500:

```powershell
flutter run -d chrome --web-port=5555 --dart-define=API_DEMO_FAIL=500
```

## Проверка

```powershell
flutter analyze
flutter test
flutter build web
```

Релизные сборки для репозитория `airline-practice`:

```powershell
flutter build web --release --base-href /airline-practice/ --dart-define=API_BASE_URL=http://localhost:8080/api
flutter build web --release --wasm --base-href /airline-practice/ --dart-define=API_BASE_URL=http://localhost:8080/api
```

При публикации workflow копирует `index.html` в `404.html`, поэтому прямые ссылки на внутренние маршруты загружают Flutter-приложение вместо стандартной страницы 404.

На Windows сборку следует выполнять из пути без кириллицы: компилятор шейдеров Flutter не умеет записывать часть ресурсов в каталог с русскими буквами.
